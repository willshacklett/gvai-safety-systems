Safety is a boundary to verify, not a promise to assume.

04 Developer pilot
Expressions of interest

Invite-Only Advisory Pilot

Explore an advisory decision API for your application's telemetry and reported action effects. Get structured recommendations you can inspect and integrate into your own review process.

Inquiries only; access is not activated by this page. Hosted pilot access is subject to operator approval and operational validation. Paid subscriptions are not available. There is no signup, checkout, or live advisory API connection on this website.

Three outputs. Your controls stay yours.

  • ALLOW: the supplied sample meets the evaluator's advisory rules. It is not permission to execute.
  • QUALIFY: review the supplied sample before proceeding.
  • BLOCK: the supplied sample triggers an advisory rule; the recommendation does not stop execution.

Results use caller-supplied telemetry and reported effects, not independent observation of your system. An omitted or inaccurate report can limit the recommendation.

A bounded, operator-led evaluation

  1. Discuss a non-sensitive use case with our team.
  2. Before approved access, agree a finite evaluation allowance, expiry and project scope. No unlimited access or automatic renewal is offered.
  3. An operator provisions your tenant and project, then arranges private, one-time API-key delivery. Keys expire and can be revoked; retain them securely.
  4. Send authenticated evaluation requests through the separately approved access path and inspect project-scoped usage.

Each newly reserved attempt consumes one unit, including failures or lost replies. Exact request-ID retries do not run the evaluator again; they do not retrieve a previous result. Pilot access ends at its expiry or cap and can be suspended.

What an integration looks like

Illustrative contract examples, not live results or a public endpoint. Approved clients use POST /v1/evaluations with a bearer API key in the Authorization header and Content-Type: application/json. Replace the example request and project IDs with your own opaque request ID and operator-provided project ID. Never put credentials in URLs or email them.

Example JSON request

{
  "version": "v1",
  "request_id": "req-2026-001",
  "resource_id": "project-a",
  "telemetry": {
    "token_delta": 100,
    "tool_calls_delta": 1,
    "error_delta": 0,
    "repeated_action_delta": 0,
    "recursion_depth": 0,
    "latency_ms": null
  },
  "reported_effects": []
}

Illustrative JSON response

{
  "outcome": "evaluated",
  "reason": "evaluated",
  "evaluation": {
    "version": "gvai-evaluation-v1",
    "request_id": "req-2026-001",
    "decision": "ALLOW",
    "risk_score": 1.45,
    "risk_band": "green",
    "explanation": "The existing telemetry guard classified this sample green. No authority-expansion effect was reported. This is not authorization or enforcement.",
    "evaluation_status": "ok",
    "advisory_only": true,
    "enforcement_applied": false
  }
}

Advisory is not enforcement. This API does not execute actions, independently enforce shutdown, terminate processes, or establish confinement. It provides no certification, availability, security, or termination guarantee. Independent shutdown research remains experimental and separate from this pilot.
